# M4.1：全网候选结构、截止点报告集合与可选信息模块

2026-10-10。承接服务器作业1171068的M4.0工程通过。本轮把真实原训练X与报告位置接到可检查的非空候选结构，并实现用户提出的“有信息可加入、缺信息可关闭”及信息对照设计。原3604训练记录、496站和原主干事故输入保持不变；没有开展真实监督训练或读取验证/test交通。

## 信息模块与对照

`InformationProfile`提供两个独立开关：`new_reports`与`ramp_exchanges`。输入读取器记录每项的available/requested/enabled/missing_reason。关闭新增报告得到空报告张量，容量仍可由历史生成；没有新增报告源时该模块明确标为缺失。原ICSF/TIID的触发报告始终保留。

| 配置 | 新增报告集合 | 已知匝道交换 |
|---|---|---|
| ramps_0_reports_0 | 关闭 | 关闭，含匝道区间断开 |
| ramps_0_reports_1 | 开启 | 关闭，含匝道区间断开 |
| ramps_1_reports_0 | 关闭 | 显式开放交换 |
| ramps_1_reports_1 | 开启 | 显式开放交换 |

固定匝道配置比较报告开/关，检验新增事故信息的增量价值。固定报告配置比较两种结构，检验匝道交换假设、覆盖和边界变化的组合价值；不能把它写成纯粹信息效应。配对训练应保持共同初始化、历史、样本顺序和预算。全部496站是主评价范围，另外报告两图共同结构站点及新增覆盖站点，保持共同目标有效掩码。原事件展开评价保留；同截止点1/重复数权重仅作为独立敏感性分析保存。

产物`information_ablation.json`冻结这四种输入组合和比较规则；它是设计清单，尚无预测结果。V2既定F/N0/N1/P0/P1/L1对照仍保留，不能用四种信息组合替代受限结构对普通结构的主检验。

可选模块只能省略相应附加信息。合法历史、基本道路身份和传播所需连接仍是基础前提；缺失时保留主干输出，并记录新增机制缺口，不将回退计入共同资格。

## 两种候选图

用完整2217行源站表核对原496站道路、方向、位置与里程。N/E按Abs PM递增、S/W递减仍是显式假设，尚未由独立拓扑资料认证。不同路线/方向不连接；重合位置/里程、额外主线实体、数值重复来源及未知连接器导致切断。至少三个不同站ID的连续链才进入候选结构；数值重复的8站全部保留在目标轴，但不能凑传播链。

保守图将包含任何非主线站的区间切断。另一图允许已知On Ramp/Off Ramp：入口集总映射到相邻下游观测节点，出口到相邻上游节点；在观测站位置上的匝道附着该站。一个节点的同类匝道合为一条开放边，并保留全部源匝道ID。端点及连接缺口另有开放边界；不在无道路依据的任意内点增加源汇。未映射匝道ID单独保存。

全部内部/出口共享发送预算，入口与内部入流共享接收预算。有出口分岔时采用固定等分发送权重，**这是待做敏感性检查的集总先验，不是实测转向比例**。入口需求由原共享历史边界预测器生成，不读取未来匝道观测或新增报告。道路物理长度、真实匝道位置网格及车辆单位仍未认证。

本地真实TRAIN-X结果：保守结构216/496站；显式匝道结构476/496站，约96.0%。这描述元数据假设下的候选结构可用性；源插补时点、独立观测实体、直接方向连接及报告版本资格未闭合，因此`jointly_certified_nodes=0`、`majority_joint_gate_passed=false`、`main_training_ready=false`。96.0%不能替代V2要求的至少397站联合资格。

## 报告集合

从已取得的v8原表中提取7999条按源incident_id去重的训练期位置记录。原表476768行，2行时间不可解析；本次筛选范围内没有冲突ID。数据摘录随仓库保存，保留CC BY-NC 4.0归属与源哈希；服务器无需取得完整原始事故表。

对每个原训练截止点取`[t0-60分钟,t0]`内记录；不按最终duration判定活跃/清除，不使用Type、DESCRIPTION或LOCATION文本。60分钟是本轮固定记忆范围，不代表真实事故持续时间。发生、录入和首次发布无法由dt区分，继续采用现有离线条件协议的“记录时间和位置在首报时可用”假设；不能认证在线可用性。

同路同向且位于候选内部边里程区间的记录，再按位置到端点直线段距离不超过1km做交叉检查；距离不是行驶距离或道路长度。旅行方向半开区间处理共用站点，单报告最多直接影响一条内部边；入口不接受报告容量关联。其他位置保留为未关联记录，不扩散成整段容量掩码。每个信息配置重新建立自己的报告—边索引，避免两图边轴混用。

3346个独立截止点共13035次报告成员关系，2916个截止点含多个报告，最多15条。所有3604条原触发身份/时间/位置特征逐条精确重放，原主干继续使用各自触发条件。同一截止点共享新增历史和完整筛选报告集合，但不把不同原触发条件的预测宣称为相同预测。

真实输入回读只做无梯度递推，确认新增报告只改变容量系数，初态、边界和初始零投影保持一致。初始预测差0是零初始化的预期行为，不能视为信息无效或收益证据。本轮没有主训练器、真实优化更新、预测MAE或L1/历史前缀监督的新实现。

## 服务器执行

先在终端独立更新`research/chronological-tiid`分支，再提交：

```bash
bash experiments/chronological/submit_incident_capacity_network.sh
```

入口默认gpu_v100、1GPU、3CPU、15分钟；内存由集群自动分配。显式传递仓库路径，日志在仓库根目录`slurm-capacity_m41-作业号.out`。复用M4.0既有数据/历史，必要时可设置`M41_PYTHON`、`M41_DATA_DIR`、`M41_SENSORS`、`M41_HISTORY_DIR`；兼容已有M40数据环境变量。可将原v11a历史目录作为唯一位置参数。Bash不含Git、下载或安装命令。

在已有GPU分配中可直接运行`run_incident_capacity_network.sh`；默认设备CPU，可设置`M41_DEVICE=cuda:0`。本轮成功标记为`M41_NETWORK_INPUT_PACK_COMPLETE_EXPLORATORY`及退出0，结果在新建的`contra_network_m41_.../pack`目录。
