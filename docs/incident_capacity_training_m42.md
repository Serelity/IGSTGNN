# M4.2：六组共同训练、局部对照与历史前缀监督

2026-10-10。承接服务器M4.1作业1171369（46项全部通过，候选覆盖216/476站）。本轮实现真实监督的工程闭环，继续研究“新增事故报告→容量→传播→原预测”的价值。原任务3604训练、917验证、496站、12个目标窗口不变。test不读取。候选图、源插补时点和报告首发版本证据未闭合，运行与结果统一标为探索性。

## L1局部对照的方程

L1保留P1的历史编码、四控制点容量、历史驱动边界、辅助头及融合投影，替代预测阶段的动态空间耦合。复用同一低维历史边界预测器，在各节点给出四控制点需求曲线B_i(t)，不增加新的自由逐时刻网络。内部边e=(i,j)的预测到达需求为p_e B_i(t)，入口边仍为B_j(t)。该需求只依赖截止点前的历史。

非入口到达出价为`a_e=min(p_e B_src,c_e)`，入口为已预测边界需求。本站接收缩放为`lambda_i=min(1,beta_i(1-x_i)/sum_In a_e)`，零入价时缩放定义为1。入流`I_i=sum_In lambda_i a_e`。本站流出为`O_i=sum_Out min(p_e alpha_i x_i,c_e)`。更新`x_i_next=x_i+h(I_i-O_i)`。

未来递推不读取邻站未来状态。发送与接收界及既有步长条件保持状态在[0,1]，不用事后clip。内部边的到达估计和离开估计刻意分开，不声称它们是同一界面交换量，也不声称全网潜收支守恒。该对照有正常历史预测入流，不能将其视为删去全部入流的排空模型。边界网络参数数目与P相同，但L1在更多节点使用该网络，其有效使用范围与计算已披露。

## 较早历史前缀监督

固定新截止点`t0-20分钟`。原X槽0:8输入新任务，左补4个“缺失”槽，仍使用12槽编码接口；这些观测在新截止点相对标签为-45至-10分钟。原X槽8、9不进入前缀任务。原X槽10:12只作为辅助目标，对应新截止点后的[5,10]与[10,15]分钟。

初态、历史摘要、边界全部由这个较早前缀重算。新增报告重新取新截止点前60分钟的记录，重新计算年龄；原触发报告通常尚未发生，因此前缀任务不调用原主干事故路径。前缀只在训练集运行。辅助读出与主任务使用同一递推、同一窗口聚合和同一个观测头，只递推到15分钟；不把被完整输入的观测再原样重建。

新报告摘录10777条来自同一公开v8源表，包含原train/val截止点及训练前缀截止点的回溯记录。没有新增监督样本、目标、事故类型、描述或持续时间。时间可用性与位置首报已知仍是假设。源、许可、字段及哈希见`report_metadata_m42/README.md`和manifest。验证报告位置与原主干逐条重放；验证交通只参与评价，归一化、图和候选排除规则均来自训练。

## 损失、指标与检查点

保留原训练的原单位pooled MAE作为主损失。辅助读出预测冻结训练scaler的z分数；未来Y辅助MAE与前缀辅助MAE各占一半，再乘lambda_obs=0.1。容量正则为主任务及前缀四控制系数二阶差分平方的平均，lambda_curve=0.001。规范化附加项乘训练std后加到原单位主损失，使权重对应可比较尺度。N/P/L使用完全相同损失；F保留原损失。

继承原batch48、Adam lr0.002、weight_decay1e-5、clip5、100epoch上限、patience20及原学习率调度。首轮默认只完成1个epoch（每组76次更新），保留epoch边界检查点；它用于工程和训练成本检查，尚未达到V2建议的5%至10%完整预算。旧F检查点不复用。

选择键沿用原`all_nodes.mae_macro`：各时距有效目标pooled MAE的宏平均。另列`station_horizon_macro_mae`（先各站×时距平均再等权汇总），避免把两种权重口径混写。保持共同有效目标掩码，输出全496站、共同216站、额外覆盖站、当前候选、边界、14方向组及各时距。没有有效目标的区域返回null。正式统计区间与五种子实验不属于此次工程短跑。

每组保存last_checkpoint、best_model、best_validation_predictions、best_validation_metrics和summary；共同输入、源代码、协议、初始化哈希与训练顺序均记录。续跑核验身份并恢复优化器/调度器；逐batch确定性种子保证下一轮可复现。早停规则相同，实际更新数和最佳epoch分别披露。成对差值统一`对照MAE-候选MAE`，正值表示候选较好。

记录容量限制、接收限制、潜状态范围及P组收支残差；分支总梯度与每epoch前两批的**纯主预测损失到容量网络梯度**分开保存，避免用曲线正则的梯度冒充容量参与主预测。真实零响应允许出现，不能仅凭工程测试推断收益。

## 服务器运行

独立更新代码后：

```bash
bash experiments/chronological/submit_incident_capacity_training.sh
```

默认gpu_v100、1GPU、3CPU、2小时；没有显式内存参数。复用原v11a历史并自动发现，默认六组各1个完整epoch。无下载、安装或版本控制命令。日志`slurm-capacity_m42-作业号.out`，结果位于`contra_training_m42_...`。

已在GPU分配中可直接执行`run_incident_capacity_training.sh`。环境变量`M42_DATA_DIR/HISTORY_DIR/SENSORS/PYTHON/DEVICE`可覆盖默认值，兼容既有M41/M40数据变量。`M42_NETWORK_DIR`可复用已验证的M4.1 pack，省略时自动重建同一候选输入包。

续跑到绝对epoch5（须使用原运行身份、相同代码/环境）：

```bash
M42_RESUME_RUN=/absolute/path/contra_training_m42_... M42_EPOCHS=5 \
  bash experiments/chronological/submit_incident_capacity_training.sh
```

`M42_CHECK=1`仅首4条train/val、batch2，每组2次更新，禁止将其排名解释为预测收益。完整1epoch也不能替代成对多种子结论。探索性运行不解除`main_training_ready=false`、`jointly_certified_nodes=0`或在线可用性限制。
