# Chattanooga 数据审查：暂不进入物理模型训练

日期：2026-10-09。本次完成两个已下载 ZIP 的全量窗口审查，没有训练、插补、截断异常值或改变原始文件。结论是 **`DATA_AUDIT_COMPLETE_NOT_TRAINING_READY`**：可继续作为事故机制研究的数据候选，但当前发布版本不能直接用于容量、车辆守恒或点队列参数标定。

机器结果见 [audit_summary.json](chattanooga_data_audit_summary.json)，独立数值复核见 [independent_numeric_checks.json](chattanooga_independent_numeric_checks.json)。原始文件来源与 SHA256 见 [下载清单](incident_physics_alternative_downloads.json)。

## 审查范围与方法

- 全部 `allData`：18,059 个 CSV，包含 702 个事故窗口、17,357 个无事故窗口，共 1,119,658 行；没有截断文件或跳过坏行。
- 全部 `bestData`：9,329 个 CSV 与 `allData` 对应文件逐字节一致。其中 361 个事故、8,968 个无事故窗口，不能重复计入样本量。
- 元数据：181 个站点、1,593 条事故记录；检查字段、拓扑关系与报告时间校正。
- 缺失、越界、时间及重叠检查为全量；数值均值、标准差及极值为全量。稳健分位数、MAD、IQR 及截尾敏感性仅基于每窗口每指标展平后每隔 19 个值的确定性样本，不是全量分位数；这些统计不用于自动删值或校准。
- 统计单位是事件窗口/站点观测，行与相邻站点不是独立重复。未拟合缩放器、插补器或任何模型，未做假设检验。

审查预先关注时间、缺失、重复观测、字段可用性及物理边界。发现异常值后增加了十进制独立复核、日期配对检查和局部窗口可用量估算；这些属于探索性检查。

## 1. 时间网格整齐，但对照窗口的日期字段不能直接使用

全部 18,059 个窗口均为 62 行，步长严格为 30 秒，没有窗口内重复或逆序时间。相对于文件名的报告钟点，范围统一为 **−900 秒至 +930 秒**，即 −15 分钟至 +15.5 分钟。474 个窗口跨午夜，需结合报告日期处理日期进位。

其中 17,357 个无事故窗口的 CSV `date` 全部与文件名日期不同，差值为非零整周，最大绝对差为 175 天。使用 `站点 + CSV date + 报告钟点` 配对，可以把其中 17,042 个窗口对应到唯一的已发布事故窗口；315 个窗口没有找到对应事故窗口。这支持 `date` 保留了配对事故日期的解释，但没有发布转换代码或显式父事件 ID 供进一步认证。

**若直接用 CSV date 构造对照样本时间或划分训练集，会把不同周的观测放到错误日期。** 此次审查以文件名日期和 `data_time` 构建时间；该解释符合作者对文件名的说明，并与跨窗口重叠测量一致性检查相容。

元数据有 907/1,593 条报告时钟相对原始值加了 12 小时，与作者说明的 AM/PM 修正相符；这不是对实际事故发生时刻的认证。若将时间解释为 Chattanooga 当地民用时间，发现 5 个对照窗口落在秋季重复小时、4 个落在春季不存在小时。原文件没有时区及 fold 标识，需单独核实，不能默认全部转 UTC 正确。

即使定义报告后 15 分钟任务，也应明确使用 +30 至 +900 秒的 30 行，并处理 0 秒和 +930 秒两行。聚合时间戳代表区间起点还是终点尚未确认，所以这还不是最终无泄漏输入/目标协议。

## 2. 发布文件存在不能直接用于物理计算的数值

以作者完整邻域子集中的 **361 个事故窗口**为例：

| 检查项 | 全量结果 | 含义 |
| --- | --- | --- |
| 流量缺失 | 31,909 / 246,202 个站点时刻，12.96% | 完整邻域不等于观测完整 |
| 流量 > 1,000 | 21,087 / 214,293 个非缺失值，9.84% | 探索性异常筛查阈值，不是道路认证容量 |
| 流量 > 1,000,000 | 2,626 个值 | 与“30 秒车辆计数”解释明显不相容 |
| 含流量 > 1,000 的窗口 | 80 / 361，22.16% | 异常影响多个事件，不是单个离群点 |
| 占有率 > 100 | 31,639 / 214,293 个非缺失值，14.76% | 与发布文档的百分比口径不相容 |
| 11 站流量全时段非缺失 | 48 / 361 个窗口 | 仅检查完整性，尚未排除异常值 |
| 11 站三指标全时段非缺失 | 17 / 361 个窗口 | 不能把其余窗口全部解释为无交通 |

独立使用 `csv.DictReader + Decimal` 重读全部 361 个事故窗口，得到完全相同的异常计数。原始流量单元格最大值为 **812612121161179125**；占有率最大值约 **1.02×10²²**。它们存在于发布 CSV 中，不是本次浮点计算才产生的数值。

全部 `allData` 中，流量 > 1,000,000 的值有 132,387 个，占有率 > 100 的值有 1,352,385 个。目前不能区分这是源记录问题、车道聚合问题、发布转换错误，还是其他原因；**不能擅自除以某个倍率、裁到上限，或声称修复成功**。特别是未经确认的异常流量不能积分成“队列车辆数”。

速度缺失要区别对待：全量扫描中，471,128 个站点时刻是“流量为 0、速度为空”；没有发现“流量为正、速度为空”。另有 3,458,266 个站点时刻三个指标同时为空。前者与零车辆时没有平均速度的定义相容，后者需要按观测缺失或未覆盖邻居处理。拓扑未映射的邻居也可能来自引用错误，不能一律视为真实道路末端。

## 3. 随机按文件划分会有共享观测泄漏风险

窗口文件的站点标识与拓扑 `Name` 格式不同，必须通过明确的 `Road + Heading + Mile` 建立一对一映射。修正映射后，18,059 个中心站点全部对应成功；不能直接字符串比较后把映射失败解释成“没有重叠”。

在 `allData` 内检查每个邻域站点、日期及精确时间戳，得到：

- **6,582 对窗口**共享站点时刻；涉及 **8,224 个窗口（45.54%）**。
- 其中 2,860 对的两个窗口都属于 `bestData`。
- 455 对来自事故/无事故两种窗口标签。这是窗口级标签与共享观测的关系，不能直接判为事故标签错误。
- 重叠位置共有 3,150,986 次双侧有限数值比较，差异超过 `1e-6` 的数量为 **0**，支持它们确实重用了同一观测。
- 重叠连接组最大为 8 个窗口；没有在 `allData` 内发现整个文件逐字节重复。

按实际观测日期做“11—2 月训练、3 月验证、4 月测试”的**覆盖诊断**，未发现这些重叠对跨越上述月份边界。这尚不是正式划分批准：未映射邻居、夏令时、配对选择、特征可用时点仍需处理。

按中心站点、星期、报告钟点得到的 715 个配对组全部跨越这三个时间段。时间划分可以隔开已识别的原始观测，但不能据此声称配对事件家族独立。后续需明确研究的是同一道路未来日期泛化，还是独立事件/地点泛化；不能把配对控制组当成任意独立样本计算不确定性。

## 4. 拓扑有用，但还不是已认证的物理走廊

181 行拓扑中，338 条有向前后邻接能找到目标、互相对应，且道路与方向一致；长度都为正，与两站 `Mile` 的绝对差在浮点误差内一致。另有 20 个空端点引用，以及 **4 个非空但找不到目标的引用**，需要进一步核实。

这些证据支持道路顺序和里程差的使用，但没有提供匝道流量、车道数量与汇总规则、有效路段储存、容量参数或队列真值。原论文的数据集用途是事故检测；不能把“有邻居关系”直接提升为无匝道守恒走廊。

## 5. 能否缩小范围支持我们的研究

作为可用量诊断，检查报告前 15 分钟与报告后 15 分钟，仅用中心及直接上下游三站，要求流量非缺失且位于 0—1,000、占有率 0—100、速度 0—120 mph（流量为 0 时允许速度缺失）：

| 范围 | 通过上述探索性筛查的事故窗口 | 11—2 月 / 3 月 / 4 月 |
| --- | --- | --- |
| `allData` | 247 / 702 | 148 / 39 / 60 |
| `bestData` | 174 / 361 | 104 / 27 / 43 |

这些是**覆盖估算，不是清洗完成的训练样本**。阈值不保证剩余值正确；筛查还利用目标期观测，不能直接把它转为只保留“未来观测完整且正常”样本的训练/部署规则。匝道、事故首次报告信息与物理观测边界也没有因此补齐。

可考虑的任务仍是报告时刻附近的 5/10/15 分钟预测及局部传播检查，无法直接复用原 IGSTGNN 的 60 分钟目标。即使后续排除或修复异常，也应比较完整 fixed、同输入自由递推与物理分支，避免将改任务、加速度/占有率带来的变化当成物理模块贡献。

## 字段使用约束

| 字段 | 数据字典与当前判定 |
| --- | --- |
| `volume` | 发布说明为每 30 秒车辆计数；应非负。发现重大异常，车辆尺度尚不可直接用于物理积分 |
| `speed` | 发布说明为 mph；车辆为 0 时可为空。平均方式、车道汇总与聚合时间边界尚待核实 |
| `occupancy` | 发布说明为百分比，合理范围 0—100；发现重大越界，不能直接作密度代理 |
| `incident_time` | 报告钟点；不是事故真实起点，精确可用延迟未知 |
| CSV `date` / 文件名日期 | 对照窗口含义不同；分别保留配对日期与观测日期，不静默覆盖原字段 |
| `incident at sensor (i)` | 事件窗口标签。若用于报告后的回归，需明确“此刻已接到报告”的假设；不能当作此前已经观测到的事故状态 |
| `type`、伤亡等事故属性 | 事后整理字段的首次可用时点未认证；不能默认在预测发起时已知 |
| `weather`、`light` | 作者派生资料；未来行的天气不能当作已知历史，历史可用性与天气预报情景需另定 |
| 拓扑和里程 | 有静态元数据；缺少完整物理边界、车道与容量依据 |

没有检测限/饱和阈值或故障码字典；空字符串按缺测统计，零保持为零。此次没有主动变换任何观测或剔除窗口。

## 下一步与复现

下一步应追溯作者发布转换代码、原始雷达数据或修正版，解释流量和占有率异常，并固定控制窗口日期映射；在此之前不开始物理训练、不把插补或截断当作数据问题已解决。未向作者发消息。现有 Contra 主实验没有换数据，H1 的原数据契约缺口也没有解除。

已下载数据的机器上，可运行以下只读审查；输出目录必须是新目录，避免覆盖证据：

```bash
python experiments/chronological/audit_chattanooga.py \
  --data-dir /path/to/chattanooga_2024 \
  --output-dir /path/to/new_audit_output
```

本地环境为 Python 3.10.18、NumPy 1.22.4。脚本校验两份归档 SHA256，限制成员大小与数量，不解压执行任何代码。跨午夜、站点别名、零/缺失区分、重叠枚举及非法输入的 7 项针对性测试通过。无需服务器 GPU 作业。

本地完整输出在 `论文学习/替代公开数据检索_20261009/chattanooga_audit_final/`，含脱离原始行值的逐窗口审查表；仓库只保存代码、汇总与报告。初版 `chattanooga_audit_v1` 的站点映射未完成，重叠及映射缺失结果已作废；`v2` 修正映射；最终版另加入未映射中心阻断检查。引用最终版，不引用初版零重叠数。
