# 既有消融对 IGSTGNN 内部事故建模的启发

日期：2026-10-10。范围：本地源码、已有结果记录、保存的服务器日志与结果摘要；没有新增训练或推理，没有查看 test 指标。**现有实验足以约束下一轮设计，但还没有验证新的内部事故—容量—传播模块。**

## 1. 先纠正比较对象

目前 M4 系统是完整原 IGSTGNN 加额外分支：原 ICSF 注入历史，原 TIID 调整预测隐藏状态，新增容量/传播分支在 TIID 后、输出头前加入 `forecast_delta`。源码见 `src/models/igstgnn.py`、`src/models/incident_capacity_fusion.py` 和 `experiments/chronological/train_incident_capacity.py`。

因此 P1 的报告 ON/OFF 只回答“保留原事故路径后，新增报告容量路径还有多少边际作用”，没有回答“我们设计的事故模块是否优于原 ICSF/TIID”。新增分支效果很小，可以来自设计不足、输入重叠或其他原因；这次探针不能区分这些解释。

研究主线应回到：**改造 IGSTGNN 内部的事故注入与传播机制，用原模块作为直接参照。** 原模块可以逐项修改，不要求同时删掉 ICSF 和 TIID。旧 M4.6/M4.7 容量残差方案保留为历史候选，不再直接作为默认下一轮开发任务；旧训练和结果协议不变。

上述不同实验的样本、切分、输入和评价端点并不完全相同，不能横向把 MAE 排成模型排行榜。旧结果约 22 与当前 M4 约 26 的差别也不能解释为同协议下的优劣。

### 2.1 ICSF：可以确定的问题，以及不能推出的结论

当前单报告、关闭静态传感器属性的路径可写成：

```text
H_last_new = LayerNorm(H_last + candidate_mask * V(report))
```

这不是整个模块失效：V 和候选位置仍影响历史，历史改变还会影响动态图及后续预测。K 与连续距离另有 TIID 用途。也不能把 softmax 改成沿节点轴就称为修复原论文公式，那是改变模型定义。

真正的设计缺口是：在这条注意力中，节点交通状态与距离不能控制报告的绝对注入权重。但“改成 sigmoid”本身不是足够的新设计——强度门控和多层事故门控已经没有获得稳定收益。必须说明新的状态、学习信号和传播约束为何有不同的作用。

### 2.2 TIID：显式衰减很短，不代表所有事故影响都很短

固定 `sigma_t=1` 时，H1/H3/H6/H12 系数约为 0.6065 / 0.01111 / 1.52e−8 / 5.38e−32。TIID 显式附加项很快衰减，但 ICSF 可经时空主干影响晚期预测。v12a/b 中 ICSF 相对 norm_only 在候选 H1–H6 / H7–H12 的收益约为 0.116298 / 0.182014。

因此可以质疑“独立事故向量乘固定曲线”的表达方式，不能断言原模型没有长程事故响应。A 到 C″ 的负结果进一步约束了方案：状态递推若作为新候选，必须由交通状态和传播过程决定后续影响，而不只是换一种更长的报告衰减曲线。

### 2.3 P2 的层结果提供线索，不提供最优结构

以 `OFF−ON` 为符号，正值表示开启该层更好：

| 单独关闭新增事故门控 | 全网 MAE 差 | 关联节点 MAE 差 |
|---|---:|---:|
| 第 1 层 | −0.000247 | +0.011946 |
| 第 2 层 | −0.012786 | −0.031877 |
| 第 3 层 | +0.004320 | +0.045381 |
| 第 4 层 | −0.002426 | +0.001614 |
| 第 5 层 | −0.001156 | +0.009503 |

这些是在同一个 ACDG 检查点上关闭一个新增门控分支，不是关闭整个时空层，更不是五个分别重训的结构。它们说明作用取决于层、区域和时距；不能把五个差相加，也不能据此确定“第 3 层才有用”。五种单层关闭后的全网 MAE 仍高于 fixed。ACDG 按同一早停策略完成 89 轮，fixed 完成 100 轮，实际更新预算不同。

## 3. 更有根据的模型候选

建议的研究假设是：**用一个交通状态条件下的事故状态，统一组织事故注入、有效通行性变化和空间传播，而不是并列输出多个事故修正项。** 它尚未实现，也没有精度结论。

```text
合法历史交通 + 截止时点可用的报告位置/年龄
                 ↓
      历史状态条件下的事故状态估计
                 ↓
      有界的有效通行性/交换能力调制
                 ↓
 IGSTGNN 内部外生空间分支中的受限状态更新
                 ↓
      与原内生时间分支共同形成预测
```

与已做方案的实质区别应体现为：

1. **事故描述与交通响应分开。** 报告是证据，交通状态决定当前响应；同一报告不默认造成相同的节点扰动。没有严重度或封道字段时，不虚构这些输入。
2. **改内部状态更新。** 新状态应进入 IGSTGNN 的空间传播计算，改变隐藏状态如何交换，而非保留原事故全路径后再加一个输出残差。固定原内生时间分支和预测头，先控制一个改造因素。
3. **让时间响应来自递推。** 需求不足、下游受阻及状态恢复可以产生不同轨迹，不预设一个对所有场景相同的报告衰减函数。既有有界交换算子可复用，但接入、尺度与对照需要重新设计。
4. **对物理含义保持可检验的边界。** 当前可研究的是潜状态、共享边交换和有效交换上限；没有单位、直接连接与观测映射认证时，不称为真实容量、车辆守恒或事故因果效应。候选道路方向结构和学习图承担不同职责，不能互相冒充。

这些是由旧消融引出的设计假设，不是它们已经证明的机制。容量状态仍可能不可辨识，约束也可能损害预测；普通递推参照必须保留。全部 496 站继续参与主任务，局部资格不足需要显式回退并单报覆盖，不因非关联区域有损失就事后删去那些节点。

## 4. 下一轮如何直接回答“改 IGSTGNN 是否更好”

先冻结一个具体内部接口，不同时开发多套新模块。比较顺序如下，按结果决定是否进入后一项，不要求立即全跑：

| 对照 | 固定的部分 | 回答的问题 |
|---|---|---|
| 原 ICSF + 原 TIID vs 新空间事故接口 + 原 TIID | 主干其余部分、输入、归一化、训练和选模规则 | 内部空间事故改造是否优于原模块？ |
| 在已选空间接口下，原 TIID vs 状态递推时间接口 | 同一空间接口及共同输入 | 时间机制的改变是否还有独立收益？ |
| 新接口中的普通递推 vs 受限交换 | 事故输入、状态维度、接入位置、时间预算与读出 | 收益是否来自受限结构，而非增加参数/记忆？ |
| 对选定结构重新训练有报告/无报告模型；另做同检查点 ON/OFF | 同一归一化和数据协议，无报告模型不偷带位置掩码 | 报告提供多少训练增量，以及已训练模型怎样使用它？ |

第一项应先用原模型实际可得的单报告信息。多报告集合、额外 speed/occupancy 历史和道路资料属于信息扩展因素，单独安排；若直接进入新系统，则同时保留适配到相同信息的普通参照，并将“完整系统提升”和“原模块替换提升”分开报告。不能把模型改动和信息增加混为一项贡献。

旧 traffic_only 会连同 ICSF 的 LayerNorm 一起绕开，不能作为新的纯报告消融。原论文对齐实现可作为参考模型；需要调整共同归一化的控制模型应另命名并说明区别，避免称其与原模型完全相同。

主端点仍为冻结范围内全部站点的预测指标，辅报关联/非关联区域、道路与时距；各臂重训练，控制共同初始化、样本顺序及预算，并披露参数差异。短跑用于开发筛选，跨种子及时间段的稳定收益才能支持保留模块。旧 audit 已被反复查看，只能作开发证据，不能改名为独立确认。
