# B3-R：同一检查点的D路径ON/OFF/ON推理检查

日期：2026-10-12。该入口检查训练后的B3-R是否通过D影响节点容量、边容量、提议量Q、实际交换量、读出及流量预测。它只读开发验证集，不训练，也不读取Test。

## 在服务器运行

先等该目录的训练完全退出，再针对保存的最佳B3-R检查点执行：

```bash
cd /seu_share/home/huangkai/220243809/paper/IGSTGNN/IGSTGNN-code

bash experiments/chronological/run_b3_r_path_probe.sh \
  --run-dir experiments/chronological_runs/contra_b3r_v11_seed2025
```

不需要手工指定最佳轮次。程序读取该运行的B3R训练记录与检查点内保存的最佳模型状态，核对后选择最佳验证MAE对应的轮次。不能把第30轮等最新状态自动当作最佳状态。

脚本在登录节点自动提交Slurm，在已有allocation中直接运行，申请1 GPU、3 CPU、6小时；不使用`--mem`，不执行Git。Python固定为既有`igstgnn`环境，因此当前提示符是`(base)`也可以执行。可用`B3R_REPO_DIR`、`PYTHON_BIN`覆盖路径；仅在确有直接运行资源时使用`B3R_PATH_PROBE_DIRECT=1`。

如数据或图不在默认位置，可以明确指定原训练使用的目录：

```bash
bash experiments/chronological/run_b3_r_path_probe.sh \
  --run-dir experiments/chronological_runs/contra_b3r_v11_seed2025 \
  --data-dir /absolute/path/to/original/development/data \
  --graph-dir /absolute/path/to/original/graph \
  --device cuda:0 --threads 3
```

默认开发数据和图的位置沿用原训练入口。推理batch大小及划分固定采用原运行身份中的设置，不提供重新分批的参数。已有检查点复现曾受重分批的浮点差异影响，因此不能通过调整batch来绕过ON复现失败。

## 开关具体改变什么

| 推理阶段 | 容量更新 | 原TIID | 用途 |
| --- | --- | --- | --- |
| ON复现 | `c=.001+.999*sigmoid(P+m*D)` | 开启 | 先复现该最佳检查点保存的验证结果。 |
| OFF | 跳过整个D，`c=.001+.999*sigmoid(P)` | 开启 | 测量同一组已训练权重对整条D路径的敏感性。 |
| ON恢复 | 恢复原D路径 | 开启 | 核对干预清理及原预测恢复。 |

第一次ON复现失败时，不给出OFF效果结论；最后ON未恢复时，不把探针标为通过。运行期间不执行反向传播或优化器更新，参数和缓冲区须保持一致。输出保存在独立探针目录，具体路径由程序打印；原训练检查点及历史日志保留。

原训练保存的复现证据是逐窗口×时距的绝对误差、有效计数及样本/时间顺序，并非逐元素预测。第一次无观测钩子的ON按这些证据和最佳MAE作容差核对；本次带观测钩子的ON与本次无钩子ON、最终恢复ON才作逐元素精确比较。

探针入口会取得运行目录锁。原训练内部worker可绕过父进程锁，因此仍须确认同目录训练已退出，不能并行直启worker。结束时重新核对检查点、历史、源码、协议、数据和图的哈希；发现变化则判为失败，不给出完成结论。

该开关包含D内对历史与报告条件的联合处理，原TIID仍保留事故信息。因此它是**整个D路径的检查点敏感性**，不等于“有无事故信息”的纯信息消融，也不代替B3R_OFF从头训练。

## 结果怎么解释

全网和既定节点分组均按原horizon-macro定义计算MAE，差值统一为：

```text
gain = MAE_OFF - MAE_ON
```

正值表示开启D时该检查点预测更好，负值表示关闭D后更好。没有有效目标的分组标记不可用，不补成零。相邻窗口、站点和预测时距不能当作独立重复。

`candidate_potential`沿用旧训练器定义，只包含算子支持范围内、与报告关联的连通分量包络，不包含算子范围外的直接报告节点。后者单列为`direct_outside_operator`；`potential_only`为候选包络扣除直接关联节点。各分组可能重叠，不能把分组MAE或收益相加。

| 观察项 | 能回答的问题 | 解释边界 |
| --- | --- | --- |
| 节点容量变化 | D是否改变了容量表示？ | 这是无量纲潜容量，不是真实通行能力标定。 |
| 边容量变化 | 节点变化是否通过端点最小值进入边？ | 非瓶颈端点变化可能被最小值消除。 |
| 提议量Q变化 | 容量作为提议网络输入时是否改变候选交换？ | Q变化不保证最终交换变化。 |
| 实际交换变化 | 经容量及共享收发预算后是否仍有响应？ | 收发预算可能抵消容量变化；交换量不是车辆流量。 |
| 读出与预测变化 | 交换响应是否进入最终流量预测？ | 非零响应本身不代表预测改善。 |
| 全网与分组误差差值 | 该检查点的D路径在哪里有利或不利？ | 候选结构关联范围不等于实测事故传播范围。 |

若最终预测变化或全网收益很小，按容量→Q/实际交换→读出逐步定位，不直接判定事故信息无用。若ON优于OFF，也只说明这组权重对路径的利用；报告的因果作用、真实物理机制及跨种子稳定性仍需其他证据。

逐层trace来自同一次全路径开关，上游变化也会进入后续层；变化幅度不能当作逐层独立贡献排名，不能据此直接删层。

本次仍属于条件离线开发。报告首报时间语义、版本与在线可用性等缺失证据不会因为探针通过而自动补齐，Test继续封存。
