# GW9：预测分支身份是否在求和读出中丢失

## 证据、问题与假设

GW6、GW7、GW8 的新增结构未超过各自同预算的强 R，GW8 最终联合核未通过 0.5% 相对 R/可分离核及长时距门槛；这不支持继续扩大相同图核。匹配趋势诊断也未支持高波动群体普遍存在“上升低估、下降高估”，因此 GW9 不采用该机制作为设计依据。

本版源码事实是：原生各层 DIF 与 INH 预测隐状态先分别求和，再相加，经 TIID 与共享非线性头输出。待检验的问题是：在已经保留完整 R 预测的基础上，分支差异是否仍含有对误差有用的信息。这是新研究假设，不是由既有实验直接证明的机制。

主假设 H：相同新参数量和训练预算下，允许读出分支差异比只读总和表现更好。替代解释包括新增非线性容量、继续训练预算、特征幅度改变引起的优化差异以及重复使用开发集后的适应。GW9 通过容量对照、冻结 probe 和重新初始化的联合训练隔离其中部分解释；不能将两个读出的差异自动解释为因果的信息损失。

`reference.py` 从认证的 identity、budget、summary、四臂 LAST 状态和 BEST 角色中读取具体轮次、文件名与 SHA；不把 BEST/LAST 指标相同视为 checkpoint 相同。它同时认证修复后的 GW8 BEST/LAST 预测缓存、历史回放记录和 GW7/GW6 来源链。历史源码、模型权重、数据预处理、验证轴与 mask 保持认证值。

原生实现来源：`experiments/chronological/original_igstgnn_558ab01/model.py`。DIF/INH 聚合、TIID 调用和 gap 输出映射均取自该实现的实际执行。研究实现位于 `experiments/branch_readout_gw9/`。

## 数学定义与接口

设第 l 个原生解耦层产生四个预测块的隐状态 D_l、I_l，各形状为 [B,4,N,256]。严格采用原实现的 Python 求和顺序：

\[
D=\sum_{l=1}^{5}D_l,\qquad I=\sum_{l=1}^{5}I_l,\qquad Q=D-I.
\]

存在事故上下文时，S 直接读取本次执行的 `TIID(D+I,context)` 输出；否则 S=D+I。这里 S 位于原输出头的首次 ReLU 之前，包含原 TIID 增量；Q 不重复加入事故项，也不从 ReLU 后的表示反推。

保持整个原生 R 前向预测 y_R，分别建立：

\[
\Delta_{SUM}=W_2\tanh\bigl(W_1[S;\tanh(S)]+b_1\bigr),
\]

\[
\Delta_{BRANCH}=W_2\tanh\bigl(W_1[S;\tanh(Q)]+b_1\bigr).
\]

W_1 为 16×512，b_1 为 16，W_2 为 3×16、无偏置且零初始化；每头合计 8,256 参数。构造时保护 RNG，两头初始张量相同。SUM 与 BRANCH 中 W 代表独立训练但初始相同的参数，不共享优化后的权重。

原四块输出的第 g 个通道映射为第 3b+g 个 lead，得到完整 [B,12,N,1] 修正，最终预测 y=y_R+reshape(Δ)。这是归一化预测空间的附加读出；反归一化及任务 mask 与原引擎一致。

`BranchReadoutIGSTGNN(anchor,arm,stage,hidden=16)` 接受整个认证 GW8 R_CONTINUE wrapper，保留全部主干 state_dict 路径。`capture_features` 返回 `base/S/Q`；临时 hook 只观察一次真实原生前向中的各解耦层与 TIID，完整结束或异常时清除，不保存批次特征，不重新执行图、事故模块、dropout 或预测分支。

零 W_2 为严格嵌套退化特例，应在 train/eval、启用/禁用 autograd 时恢复相同 R 预测与前向 RNG 消耗。初始 W_2=0 可能阻断新头内部 W_1 的首步梯度，这是零初始化性质；输出投影应有梯度，W_2 变为非零后应验证 W_1 梯度。joint 中原生各层 DIF forecast 始终参与前向与训练。

## 阶段一：冻结小读出 probe

冻结整个认证 R，保持 eval；R 为零更新参考。SUM 和 BRANCH 各训练固定 3 轮，每头 246 次更新，完整 12 步损失。两个头共享每批一次真实主干前向产生的 base/S/Q，特征仅在该批内使用，不创建特征缓存或额外图像/数据输入。两个头各有独立但相同配置的 Adam，不能将两头的优化器混为一个或给候选额外步数。

BEST 从阶段零和固定三轮中选取，LAST 固定为第三轮。完成后自动写出 report.md、screening.json 和认证文件。`eligible_for_joint_screen` 是第二阶段入口，冻结 R 不属于等更新预算对照。

probe 预先要求 BRANCH BEST MAE 相对 SUM 与冻结 R 均改善至少 0.5%，LAST 相对自身 BEST 退化不超过 1%，真实值≥314 与 lead 7—12 组 MAE 不劣于冻结 R。门槛不因返回结果改变。

冻结读出失败则停止，不增加轮数、扩大隐藏维度或调整门槛。通过仅意味着在固定表示下值得继续验证，不足以认定可训练主干时仍有优势。

冻结的参数状态与前向执行标志分开审计。骨干不进入优化器、始终 eval 且不建立 autograd 图；单次骨干前向在 `torch.no_grad()` 内临时匹配源 GW8 的 requires_grad=True 标志，结束或异常后恢复 False，随后才计算小头。这样对齐源前向的执行条件，同时保留固定骨干的训练定义。此修订针对服务器阶段零精确缓存回放失败中的一项条件差异，不据静态代码认定唯一根因。源模型同批前向、缓存首批和完整阶段零继续实行精确值核对；没有引入容差放宽。

## 阶段二：同预算联合训练

只有认证的 probe 通过门槛才允许开始。三个臂重新从相同的 GW8 R BEST 张量构建；两个头重新零初始化，不导入 probe 学得的权重。R_CONTINUE、SUM_CONTROL、BRANCH_READOUT 各新增固定 5 轮、410 次更新，所有原参数共同训练，固定 seed=2025、batch=48、hidden=16、完整 12 步任务。

三臂在模型和引擎构造后重置相同 RNG、相同训练顺序。开始重置 Adam，续跑恢复原子提交的完整 epoch、优化器、调度器、数据顺序和 RNG；未提交 epoch 重放，总预算不能从 5 轮变成额外 5 轮。BEST 包含阶段零，LAST 为第五轮，不早停、不评估测试集。

锁定判据如下，全部满足才记为值得独立确认的开发候选：

- BRANCH BEST pooled MAE 相对同次 R 与 SUM 均至少改善 0.5%。
- BRANCH LAST 相对自身 BEST 退化不超过 1%。
- BRANCH BEST 在真实值≥314 与 lead 7—12 两个评价组的 MAE 均不劣于同次 R。

真实值分组只用于评价，不能输入模型。历史 ORIGINAL/GW2/GW4 通过认证缓存展示，不属于本次等新增预算对照；已有 MAE 13.50835 仅为共同起点，不能取代新训 R。

若候选仅超过冻结 R，不能排除继续训练收益；未超过 SUM，不能保留分支身份的增量价值主张；仅 MAPE/P95 更好但主判据未通过，报告指标权衡而不更换主要终点。筛查失败不授权追加预算。

## 工程验证与成本

所有 Python、模型、导入、语法检查、合成测试、真实预检及训练都在服务器执行。本地只进行文件字节、文本和 Git 检查以及人工静态审阅；没有服务器日志时不得写“测试通过”或“模型提升”。

服务器先执行源码包验证、四组新增测试，再做真实 batch 48 的零更新预检。预检核对 train/eval 精确退化与 RNG、全部原生 DIF forecast 梯度、新读出投影梯度、probe 主干冻结、与源前向及验证缓存的一致性、缓存清理、完整前反向耗时与显存。临时 train 检查造成的 BatchNorm 缓冲改动在正式实验前丢弃，不写入源 checkpoint，也不导入正式训练。

probe 保存执行预算及共享前向成本，joint 保存参数量、完整前向计时与训练记录。新增头只有 8,256 参数不等于系统计算便宜：probe 仍需真实主干前向；joint 仍需完整主干前反向。不能只报告新头 FLOPs 而忽略主干成本。

## 相关工作与贡献边界

分解、双分支与融合不是本版首创。相关背景包括 [D²STGNN](https://www.vldb.org/pvldb/vol15/p2733-shao.pdf) 和 [STWave](https://doi.org/10.1109/ICDE55515.2023.00046)；这些先例使“增加两个分支再融合”本身不足以构成强创新。GW9 先隔离已有原生预测分支身份是否仍有价值，后续贡献只能由真实受控结果支持。

前期冻结 probe、joint 和多版方法均重复使用相同开发验证集；即使全部门槛通过，也仅是单种子开发筛查，不是统计显著性或普适优越结论。方法与预算冻结后仍需独立确认。S/Q 的不同非线性和幅度可能改变优化，容量控制并不能完全排除它；Q 也不能直接命名为拥堵、趋势或物理传播机制。
