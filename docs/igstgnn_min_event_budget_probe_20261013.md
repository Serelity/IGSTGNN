# MIN-I1.0：最佳验证检查点的事故预算机制回读

初稿：2026-10-13；实现验收：2026-10-14。本轮对已经训练的 MIN-I 权重做验证推理和受控干预，目的是区分“适配器学到了数值变化”“变化进入了预测”和“预测变化降低了误差”。本轮不增加训练轮次、不更新参数、不评价测试集。

## 实验问题

首版 A / L / S 分别是 MIN、位置条件预算、位置加类型/描述条件预算。独立训练的 S−L、L−A 衡量模型方案的训练结果；在同一个 S 检查点上关闭语义或整个新增预算模块，衡量当前权重对这些条件和运算的依赖。两类比较应分别报告，不能用一个推理开关代替重新训练的模型对照。

新增适配器在每层、每个局部交换子步读取当前状态，更新关联内部边的无量纲预算。局部诊断中 C 与 C0 的通量差，是在相同当前 ON 状态下重新计算两种预算及各自提议的结果，不是完整模型 OFF 轨迹。完整 ON/OFF 推理应从历史输入重新走完整网络。

S 另做语义 UNK 和联合打乱诊断。UNK 将类型、描述都设为独立未知类别并将有效标志置为假；它是在没有自然缺失语义样本训练证据下的分布外输入，不称为同权重 L 模型。联合打乱使用固定种子，对验证集的类型、描述及各自有效标志使用同一置换，保持二者联合关系，不改 D、报告存在与关系可用性；目标不参与置换。它检查语义与当前样本的配对是否有用，不识别真实事件语义的因果效应。

## 数据与评价口径

- 使用同一作者发布 Contra Costa 数据、3909 / 837 / 839 切分、原标准化和站点顺序；读取全部 12 历史槽，监督原 12 目标槽；历史末槽时钟 offset **0**。
- 正式验证是 **837** 条。正式批次由运行身份读取，当前默认 **64**，最后一批 **5** 条，不为省显存临时改验证批次。小样本工程运行依身份使用其原 batch 2。
- 仅访问训练/验证加载器。发布 `incident_all.npy` 是对象数组，加载它不可避免反序列化测试载荷；审计记录这件事，不构造测试 loader、不检查测试事件或目标、不计算测试预测。
- 验证时先将各批预测和标签按原 scaler 逆标准化，拼接全部验证结果。掩码值与原引擎一致：若全验证标签最小值小于 1，就取该最小值，否则取 0。不是每批单独取最小值，也不是屏蔽全部小于 1 的标签。
- 保存的最佳验证 MAE 是全部有效验证点的 **pooled MAE**。回放用原 Torch FP32 掩码指标路径核对该值；逐时距 MAE 和 12 时距平均是另列诊断，不能冒充同一个选模指标。RMSE 同时区分 pooled 和逐时距 macro；MAPE 按原比例值及百分数单位明确标注，低流量分母可能放大百分比误差。
- 各时距只标第 1–12 步及相对原目标槽；不改变作者窗口或根据档案事件时间重新对齐。没有认证报告首次可用时间，结果属于发布事件属性条件下的离线检查点敏感性。

## 空间区域的解释

直接关联节点由原发布关系转为 float32 后计算 `abs(D).sum(-1)>0`，再与 `report_present`、`relation_available` 相与。类别 0 是真实事件类别；缺失类别使用独立 UNK 和有效标志。关系全零不等于无事故，候选算子未覆盖不等于无事故，显式关闭模块也不等于自然无事故样本。

候选潜传播集合采用冻结内部图的**弱连通分量包络**：将内部边双向连接，以直接关联节点及所有关联内部边两端为种子，取对应弱连通分量；外部入口/出口不作为可穿越节点。新增预算关联内部边的判据是“任一端直接关联”，因此这条边的两个端点都可能有直接交换响应，另外保存 `eligible_edge_endpoints` 区域。`region_definitions.json` 记录这些判据。该集合不是有向下游可达、严格预测支撑边界、真实事故影响区或按物理波速推得的队列范围。原图卷积及收发预算耦合仍可使集合外预测发生变化，不应把集合外变化直接判为实现泄漏。

道路组直接复用冻结图加载器返回的 `dict[道路方向名, 节点下标列表]`，例如 `I680-S`；节点下标逐位对齐发布 `sensors.csv`，不重新按站点 ID 排序。

全网贡献采用互斥的 direct / potential_only / remaining 划分和统一全网有效点分母。道路、候选潜传播、关联边端点、`outside_operator` 等展示区域可能重叠，不直接相加局部 MAE 或局部平均收益。`no_report_samples` 只由 `report_present=false` 定义；另列关系不可用样本，以及报告存在但关联支持为零的样本，避免混淆。空区域报告不可用及有效点数，不补零。当前发布验证没有经过认证的自然无事故对照，不能由人工 OFF 得出无事故部署稳定性结论。

## 回放、恢复与环境检查

读取各组 `last.pt` 的 `best_model_state`，核对检查点身份、组选取、连续历史、最早最低验证 MAE 对应最佳轮次及最佳指标。`model_state` 是最后完整轮次权重，不与最佳权重混用。原 `history.json`、`summary.json` 与检查点冲突时停止，回读工具不执行训练入口的 JSON 修复或覆盖逻辑。

先用原验证顺序和批次回放 A、L、S 的完整 ON。三个组的全部原指标回放通过后才允许任何 OFF/语义干预。原指标使用固定 `atol=1e-5, rtol=1e-6`，不因回放失败而扩大容差。检查点没有训练时逐点预测存档，因此这一步验证的是保存的汇总指标；后续每批 ON 及干预后恢复 ON 都与本轮已验证的 ON 逐点完全一致。检查所有模型参数、buffer、输入及开关保持原值；异常时也检查输入原件并清理临时 hook。仅 `eval()` 和推理模式，没有优化器更新、梯度或训练态 BatchNorm/Dropout。

Torch 版本、Torch CUDA runtime、device type、原线程数及 CUBLAS 配置按检查点身份核对；确定性算法和 TF32 设置与原训练约定一致。V100 SXM/PCIE 等 GPU 型号名称允许差异并记录来源与当前值，实际可比性由 ON 回放验证。`nvidia-smi` 显示的驱动最高 CUDA 版本不替代 `torch.version.cuda`。已有环境日志若不足以确定最佳轮次对应的 GPU，应写未知，不能填一个推测的型号。

## 收益和困难窗口

统一正收益定义为“参照误差减候选误差”。对模块 ON 与 OFF，正的 `MAE_OFF−MAE_ON` 才表示当前检查点开启该模块降低误差。逐点拆开改善与恶化，同时报告两者总量、净量、抵消比例和预测绝对变化。预算或预测变化明显，不自动代表预测更准。

固定困难窗口从 **A_ON** 参考状态按全网窗口 MAE 选择最差 10% 的完整窗口，正式 837 条均完整时取向上取整的 **84** 条；并列时按原样本下标确定顺序。“完整”指每个时距至少有一个有效目标点，不要求全部站点都有效。保存参考状态、样本下标、掩码及选择规则，七种状态沿用同一集合。各状态各自最差 5% 只比较尾部分布，不能替代同窗口配对比较。窗口可能共享交通观测，不能当 837 个独立事件重复做显著性检验。

优先联读全网 pooled MAE/RMSE、逐时距、道路、直接关联与候选传播区域、固定困难集及预算→局部通量→预测的变化链。数据本身没有真实容量、队列长度或事故影响标签，本轮不能识别真实事故因果效果。

困难集以 A 的误差筛选，适合回答“其他方案能否缓解 A 的失败窗口”，不能称独立困难集上的泛化证据。语义打乱仅使用一组固定置换，适合定位依赖；单次结果不能称为稳健的语义收益。

## 服务器运行

代码更新后，在仓库目录内运行（有 Slurm GPU 分配时直接执行；登录节点会自动 `sbatch` 提交）：

```bash
bash experiments/chronological/run_min_event_budget_probe.sh \
  --run-dir experiments/chronological_runs/contra_min_i_v1_bs64_seed2025
```

Python 入口：

```bash
/seu_share/home/huangkai/220243809/.conda/envs/igstgnn/bin/python -u \
  experiments/chronological/probe_min_event_budget.py \
  --run-dir experiments/chronological_runs/contra_min_i_v1_bs64_seed2025
```

训练目录只作为来源；回读在其内部创建全新 `min_i_probe_时间_随机后缀` 子目录。脚本不含 Git，不申请 `--mem`。不要把旧 B3-R 或旧 v8 目录传给本工具。运行时会锁定总目录及三组目录；有组仍在训练时拒绝并行回读。

可选参数为 `--data-dir`、`--graph-dir`、`--protocol`、`--output-dir`、`--device`、`--semantic-shuffle-seed`。自定义目录仍须通过原训练身份和哈希检查。`--check` 仅接受已有工程运行，不能把正式验证截成少量样本；Bash 的 `--check` 还会先运行针对性测试。无需指定 `--epochs` 或 `--batch-size`。
