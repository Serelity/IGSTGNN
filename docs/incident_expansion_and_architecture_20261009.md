# M1.0b：全网事故扩展可行性与架构选择

2026-10-09。接续用户“大部分路段共同满足架构数据需求”的要求。本轮完成来源追溯、训练期候选事件盘点、交通缓存完整性核验及模块需求表。没有创建新训练集、修改冻结基准、训练模型或打开验证/测试交通。

**决定：先把已有全网事故与交通数据对齐，再开发由共同观测驱动的相对容量状态和方向传播原型。完整 CTM 保留为有物理边界依据的局部参照。主模型的具体物理闭合关系仍需通过观测一致性检查，不能把任意隐状态加上“物理”名称就作为验收。**

## 1. 原训练事故覆盖为何较窄

来源链为：作者发布的 `incident_all.npy` → 既有事件身份旁表 → 时间划分及隔离规则 → 当前 3,604 个训练窗口 → `report_location_v1`。本轮复用已保存的旁表元数据，没有重新加载含目标的发布数组。

5,585 条发布样本的已恢复空间道路信息中，SR4 两向合计 3,955，SR24 两向 885，SR242 两向 626，SR160 两向 119；I80/I680/I580 为零。

- SR160-N 的 79 条和 SR160-S 的 40 条全部因 `insufficient_spatial_signature` 隔离。此前身份恢复要求至少 3 个非零空间支持点，而现有 SR160 每方向只有一个站。原规则用于从匿名样本可靠恢复身份；从带 ID 的原始事件重新构建数据时，应重新论证映射规则，不能机械要求三个站，也不能把这 119 条未经恢复的身份直接纳入。
- 其余 5,466 条中，5,452 条有唯一身份，14 条有多个候选；随后按原时间协议产生当前训练清单。本地时间划分代码没有另按 I/SR 路段类别过滤。
- 对 I80/I680/I580，能定位到“发布样本的既有空间关联中没有”，尚不能定位原始构建环节的具体原因。[作者公开说明](https://github.com/fanlixiang/IGSTGNN#dataset)明确未发布数据构建代码。不能据道路前缀现象断定作者存在某个字符串处理错误，也不能断言这几条道路没有事故。

## 3. 核心模块的需求与量纲边界

| 模块或计算 | 训练/推理必需信息 | 现有支持与决定 |
|---|---|---|
| 交通状态编码 | 截止时刻以前的三通道及掩码、时间标签 | 当前 496 站历史数值覆盖完整；扩展事件需重新抽取并审查 X，标准化只拟合训练期 |
| 事故条件编码 | 报告时间、道路方向及位置，不要求封道日志 | 原训练仅 230 站有直接正关联；已找到全部方向组的扩展候选，完成映射前不宣称正支持已扩展 |
| 相对通行能力扰动 | 上述信息及训练期参考状态；低维、有界事件扰动 | 可开发无量纲接口，仍需通过观测关系与参数稳定性检查；不能直接输出“损失几条车道” |
| 基本图或供需闭合关系 | 可解释的状态变量及观测映射；流量/速度/密度量纲或明确归一化约定 | 尚需检验，优先做共同观测关系审查；不能用占有率直接代密度或无限制学习所有尺度 |
| 有方向的状态传播 | 同路同向的站点顺序候选、历史状态、可学习滞后 | 12 个多站方向组共 494 站可形成顺序候选；同里程先分组/标记，方向及连续性待全网静态核对。只作为传播图候选，不能充当守恒界面 |
| 绝对波速/行驶时间 | 实际长度与相应速度单位、传播机制 | 不作为第一版必需输入；学习“几步滞后”不能报告为 km/h 波速 |
| 有限体积车辆守恒/CTM | cell 长度、密度、同口径界面流量、源汇边界及稳定时间步 | 目前无法证明多数区段满足，保留局部参照，暂不作为全网主模型强制路径 |
| 完整预测读出 | 496 站轴、原预测时距和同输入基线 | 保持完整；SR160 两个单站组仍可运行局部事故状态，但本数据不足以验证该组空间传播 |

必须先写清测量模型：`q = k·v` 使用兼容的区间流率、空间平均速度与密度，不能从三个现有数组名字自动推出。若源 flow 是五分钟车辆数，转 veh/h 需乘 12；若已经是流率则不乘。车道均值与全车道总量也不能混用。占有率到密度需要有效车长、检测器和聚合假设。

相对形式可令 `q* = q/q_ref`、`v* = v/v_ref`、`o* = o/o_ref`，参考量仅从训练期拟合，须为正并固定。正的乘法单位变换在比值中抵消，但来源的插补、车道聚合、通道语义错误不会因此消失。源单位未知时可以开发这些相对数值接口，不能据此给出绝对车辆容量、物理队列或密度。

若使用 `c*(t)=c0*·[1−a(t)]`，应固定或强约束训练基准 `c0*`，事故幅度 `a` 低维有界；不能同时任意学习基准、需求、拥挤状态和侧向交换。分位数可以作归一化参考，不能直接定义真实容量。报告后低流量可能来自低需求，必须用同输入事故关闭和需求/边界对照识别模型路径，而不是由流量下降证明容量下降。

## 4. 主架构选择及思想来源

**主线优先验证“共同观测状态—相对容量扰动—方向传播”，把所需额外资料压缩到全网可核对的道路顺序和观测定义。** 本轮没有将尚未验证的物理形式冻结成实现，也没有给模型加一个仅在三条走廊运行的必需分支。

- 从 Daganzo 的 [CTM 前驱报告（封面 July 1993）](https://escholarship.org/content/qt0b6612tk/qt0b6612tk.pdf)保留容量限制、发送/接收、拥堵传播的机制分工。完整数值守恒仍有相应网格与边界前提，不能删除条件后继续沿用结论。
- Shi 等的 [PIDL+FDL，IEEE TITS，DOI 10.1109/TITS.2021.3106259](https://arxiv.org/pdf/2106.03142)把未知基本图关系置于可学习模型中。借鉴的是“物理关系与未知闭合关系分工”；其方法仍依赖交通方程，并不是随意用占有率替代密度的许可。其状态估计结果不能直接证明本任务未来预测有效。
- [DCRNN，ICLR 2018](https://arxiv.org/abs/1707.01926)提供有向图双向扩散的可扩展计算形式。我们拟区分下游需求传递和上游拥堵影响，是需要验证的结构假设；双向图计算本身不是物理波速或车辆守恒证明。
- [Tang、Jin、Ozbay 的作者稿](https://arxiv.org/abs/2307.06267)启发观测重建与物理参数估计的分工。有限道路物理指导可作辅助，但不能作为多数道路机制已获验证的替代证据。

实现前的验收是：先检查多数道路是否具有可支持所选闭合关系的观测变化和稳定拟合，再加入事故容量条件；同时核对传播候选图。若仅少数道路通过，应调整物理关系或数据表示，而不是事后把多数道路的物理损失置零。数量、方向组、道路类型及事件支持分别验收；不得根据验证误差选适用道路。

## 5. 下一交付：M1.0c 全网扩展候选 X 包与观测一致性审查

1. 以本轮候选清单作待审来源，固定道路映射和排除规则，建立独立版本的训练期事件适配清单；按 ID、时间、空间冲突和重叠窗口审查。保留现有冻结基准，不覆盖原 3,604 条。
2. 从已核验缓存抽取全 496 站的 12 步三通道历史与显式掩码；只先生成候选 X，不训练、不读取新窗口 Y。报告各道路/事件的可用性及映射覆盖变化。候选时间会重叠，统计须按站时去重。
3. 在训练期做流量—占有率—速度关系、拥堵/自由状态覆盖和跨时间稳定性检查，冻结相对量尺度与观测假设；列出供需/基本图候选可解释及不可辨识的部分。与单位溯源并行，不反复要求难以取得的全部封道资料。
4. 据此冻结一个小型物理闭合原型及同输入普通传播参照，再实施 M2/M3。扩展集与原基准上的收益分开报告；跨道路结果不得冒充未见道路泛化。

本轮交付的是可复核的可行性审查和架构取舍，尚未完成扩展数据数值验收或证明多数道路的物理适用性。下一任务已有本地输入，不需要用户重新下载全年交通数据或重复服务器工程检查。
