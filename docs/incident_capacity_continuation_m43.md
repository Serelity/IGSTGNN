## 新入口与兼容性

`experiments/chronological/continue_incident_capacity.py`是独立外层入口。M4.2训练器、模型和其SOURCE_FILES中的文件均保持原字节；旧检查点的源哈希继续有效。新入口自己的哈希只写入续跑记录，不加入旧训练身份。

- 默认发现`contra_training_m42_*`中唯一的完整运行，排除check子集。若多个候选，打印目录并要求`--run-dir`；不按验证分数或修改时间选目录。
- 必须已有全部六组的summary、last、best、验证预测和指标。核验共同身份、源/协议/输入哈希、网络包文件、样本顺序、每轮更新数、优化器/调度器及最佳轮次。
- 保存的验证样本ID、目标和有效掩码须与原验证文件逐字节一致，预测误差须复算出原指标。没有有效目标的区域保持null。
- summary若因中断落后，只有其历史是last检查点的精确前缀才接受；继续使用检查点计数和最佳文件，最佳文件不一致则停止。缺组不会静默重新初始化。
- 调用原训练器`--resume --epochs 5`，恢复优化器和学习率状态。5是绝对停止轮次；各组总计380次更新，非额外5轮。
- 同一运行的此入口使用排他锁。异常退出会释放自己建立的锁；强制终止后若残留锁，先确认无同目录训练进程，再人工移除。

每次在原运行下新建`continuation_日期时间_标识/`，保存`before.json`、`invocation.json`、`training.log`、`process_result.json`及成功后的`after.json`。续跑前保存误差和有效计数的站点×时距充分统计量、区域指标、历史及预测文件哈希。它保留首轮结果的可核验统计，不复制全部旧预测或旧模型；原best文件仍按原协议更新。训练失败保留已有检查点和本次日志。

## 诊断与口径

全496站、共同216站、增加260站、候选476站、其余20站、边界、14方向组及12时距全部汇总。图换为保守配置时由实际掩码重算，不硬编码覆盖。

分别输出：

1. **各组最佳检查点比较**：披露每组最佳epoch，指标来自保存的best预测，可比较其余20站。
2. **同epoch比较**：由原训练历史比较每一轮的验证指标，避免不同最佳轮次造成混淆。原历史未保存其余20站独立指标；它只在best预测所属轮次可用，不能冒充最后一轮结果。

MAE保持原口径：先每个时距对样本和站点pooled，再平均12时距。另列站点×时距等权MAE、各时距误差和有效数。成对差值均为`对照MAE-候选MAE`，正值表示候选好。首轮与续跑后的充分统计量都保留，可以检查20站对全网差值的影响。

训练路径诊断直接读取已保存的原始记录：

- 容量输出层的总损失梯度最大值来自整轮、裁剪前；`main_loss:`梯度只取每轮前两批，不能称为整轮主损失梯度。非零只表示本批路径参与，不证明收益或容量真值恢复。
- 容量/接收/发送限制率按实际batch样本数加权，尾批4条不与48条批次等权；分母为全部记录的边×子步×潜通道×样本，含资格条件导致恒假的边，不能称为活跃边条件比例。N/L未记录的限制标记不填0。
- 状态极值、融合增量绝对最大值、P组潜收支残差最大值。L1不存在共享边交换，不伪造全网残差。
- 辅助、前缀和曲率项按原训练std与权重换算到主损失单位，列出附加项/主损失比例。原损失记录是batch均值，保留该口径；不把规范化辅助损失直接和原单位MAE比较，也不把它称为样本加权损失。

这次主要判断P1相对F是否改善，以及P1相对N1/L1有无额外价值；P1/P0与N1/N0检查新增报告增量。若5轮仍落后，结合梯度、容量限制、额外损失强度与覆盖区域确定下一次只改哪个因素，避免以机制图代替预测验证。test继续封存；候选结构及在线报告版本的未认证状态不变。

```bash

  experiments/chronological/continue_incident_capacity.py \
  --history-dir experiments/chronological_runs/contra_v11a_multichannel_history_02
```

默认沿用已有运行中记录的seed、设备及匝道开关，续至第5轮。若找到多个完整运行，在命令后加`--run-dir experiments/chronological_runs/contra_training_m42_实际目录`。原首轮未指定`--network-dir`，因此默认复用原运行的`network_pack`；若另有外部pack须显式传入该路径。数据/传感器默认值与原首轮命令一致，可用`--data-dir/--sensors`覆盖。

仅回读不训练时加`--audit-only`。该模式可显式审查check运行；完整续跑入口拒绝将check运行当成全训练。入口中无Git、下载、安装或Slurm内存参数。登录节点须先获得GPU分配，不在登录节点直接训练。

同日gpu05续到10轮时原身份比较拒绝，尚无10轮结果。已补[完整身份差异诊断](incident_capacity_resume_identity_fix_20261010.md)：正常续跑将打印具体不符字段，`--identity-audit-only`可只重建当前身份而不更新。原模型、训练器和拒绝条件保持不变。
