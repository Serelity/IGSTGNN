# 冻结 MIN 的事故位置预算增量小试

日期：2026-10-14。

本轮只回答一个问题：固定已有 MIN 的预测基础后，现有位置条件预算适配器能否学到有用的增量修正。它检验冻结主干上的注入路径，不把 ON/OFF 的差异直接解释为正确事故位置内容的独特贡献，也不识别真实道路容量或事故因果。

## 为什么这样做

已有 A/L/S 联合训练中，L 相比 A 的最佳验证 pooled MAE 改善约 0.04420；但 L 同权重关闭事故预算修正后仍保留这一优势。S 在 A 的固定困难窗口上有改善，关闭分支后也几乎保留全部收益。因此，本轮固定 A 的主干，将主干重新训练造成的差异从当前比较中移除。

## 固定项与唯一更新项

- 源运行：`contra_min_i_v1_bs64_seed2025` 的 **A/last.pt → best_model_state**；当前源最佳轮次是 28，程序从检查点历史核对，不硬编码。
- MIN 的 435856 个原参数及所有 buffer（包括归一化和图）固定。主干保持 `eval()`，关闭 dropout 和运行统计更新。
- 只更新已有 location adapter 的 1652 个名义参数，不添加语义编码器。位置模式中的 16 维语义输入始终为零，其对应列不提供额外有效条件。
- 原发布数据、归一化、站点顺序、图、历史 12 步和末槽时钟 offset 0 不变。正式数据为训练 3909、验证 837，batch 从源身份继承为 64，验证尾批为 5。
- 训练始终监督全部 12 个预测步；不继承源 A 的优化器、课程计数、数据顺序或 RNG。新优化器为仅含适配器参数的 Adam，学习率固定 0.001、weight decay 1e-5、eps 1e-8、梯度裁剪 5。
- 单种子 2025，预设上限 10 轮，不在本轮加入学习率搜索或更多事故分组。测试集不评价；对象数组不可避免反序列化测试载荷的事实保持原审计口径。

冻结参数不会免除梯度传播：训练前向不能整体包在 `no_grad()` 内，损失梯度仍须经过冻结的后续算子回到适配器。本轮使用独立循环，不调用会自动 `model.train()` 和切换课程长度的旧训练入口。

## 开始前和每轮的检查

1. 先用原可训练参数标志、原验证顺序及原批次回放 A 最佳权重的保存指标，固定 `atol=1e-5, rtol=1e-6`。
2. 冻结标志可能改变部分算子的 FP32 执行路径。因此另建立**权重相同、冻结状态相同的 MIN**作为严格逐点参照；与原执行路径的预测差异按标准化输出检查固定 `atol=1e-6, rtol=1e-5`，并记录原预测尺度和标准化尺度的最大差异。这是数值执行边界，不称为新增模块的收益。
3. 位置 adapter 的最后投影从零开始。第 0 轮 ON、OFF 与上述冻结 MIN 参照逐点完全一致，才允许训练。
4. 每轮验证按原批次执行 ON/OFF/ON：OFF 必须与固定冻结 MIN 预测逐点完全一致，恢复 ON 也必须逐点完全一致。
5. 每轮核对冻结参数、归一化状态、图 buffer 哈希和主干梯度；优化器只能含 adapter 参数。记录 adapter 梯度、是否更新、实际优化器步数及样本顺序摘要。

`mechanisms` 继续是同当前状态下 C 与 C0 的局部比较，不是完整 OFF 轨迹的通量差；预算与交换量均为隐空间量。

## 指标与停止扩大实验的规则

验证按全部拼接目标的最小值确定原引擎掩码。回放原保存指标使用 Torch FP32；本轮所有轮次的选模统一采用有效点 float64 汇总的 pooled MAE，避免跨口径比较。MAPE 在有效掩码内排除零分母，JSON 用比例，报告用百分数。

每轮同时输出 ON/OFF 的 pooled 和 12 时距 macro MAE/RMSE/MAPE、逐时距及 H3/H6/H12、正负误差收益和抵消、预测变化。固定困难集由第 0 轮冻结 MIN 的完整窗口 MAE 选最差 10%；正式验证 837 条全部完整时为 84 条，所有轮次保持同一集合。完整指每个预测步至少一个有效目标点。

**第 0 轮也是选模候选。**如果 10 轮后最佳仍为 0，报告“本轮没有取得优于冻结 MIN 的新增修正收益”，保留原 MIN；不把退回基线包装成改进成功。若最佳为训练轮次且验证 MAE 更低，只记录探索性注入路径增益，同时检查 RMSE、MAPE 和困难窗口的代价。一次小试不构成稳定泛化证据；失败也不能否定事故信息本身。固定困难集由验证误差选取，用于描述基线失败窗口，不是独立困难集泛化评价。

先在仓库目录更新代码，Git 命令单独执行：

然后只需运行一次：

```bash
bash experiments/chronological/run_min_frozen_budget.sh \
  --source-run experiments/chronological_runs/contra_min_i_v1_bs64_seed2025 \
  --epochs 10
```

默认独立输出为 `experiments/chronological_runs/contra_min_i_frozen_loc_v1_bs64_seed2025`。有 Slurm 分配时直接执行；登录节点自动 `sbatch`。脚本没有 Git，也没有 `--mem`。本轮 batch 不改变，以保持源验证回放条件。

中断后重跑**同一命令**，会从 `last.pt` 的最后完整轮次续跑；`--epochs` 是绝对目标轮次，不是额外增加的轮数。已到 10 轮时不会再训练。恢复 adapter、优化器、样本顺序和 NumPy/Torch/CUDA RNG，主干重新从同一个源最佳权重重建。当前和最佳 adapter 分开保存。

运行期间锁定源总目录、源 A 和独立新目录，防止源 A 同时续训；不需要源 L/S 组文件。源检查点、JSON、协议、发布文件和图源码按哈希保护。源发生变化时不混入当前实验；不得手动改 identity 配合续跑。旧 A/L/S 源代码和记录不改。新运行在检查点提交后遭中断时，仅允许按权威检查点恢复本轮自己的滞后 history JSON。

`--check` 只接受已有工程检查源；不能将正式 837 条验证截成小样本。可选 `--run-dir`、`--data-dir`、`--graph-dir`、`--source-protocol`、`--recipe`、`--seed`、`--device` 都受身份核验。
