## 1. 研究目标与问题

目标是在现有有限事故报告与交通历史条件下，改进IGSTGNN内部的事故信息使用和空间传播，使事故条件预测获得可重复的精度提升。

研究主线是：历史交通提供容量基线，报告条件修正容量，容量参与道路上的受限特征交换，交换结果进入原时空主干，最终由流量预测损失监督。

| 研究问题 | 首选比较 | 解释范围 |
| --- | --- | --- |
| Q1：更直接的报告更新能否改善预测？ | 原B3与B3-R配对从头训练 | 比较报告更新整体参数化；不分离G的独立贡献。 |
| Q2：新修正路径是否值得保留？ | B3-R ON与空间修正OFF分别从头训练 | 原TIID保留时，整个D路径的价值；不等于纯报告信息贡献。 |
| Q3：硬容量上限有何独立价值？ | 后续在同P/D下，仅移除显式边上限 | 容量仍进入提议网络，收发预算保留；不是无容量或无约束对照。 |

首轮以Q1为主要问题，Q2在大规模种子扩展前补齐，Q3后置。原B0仍是原IGSTGNN同输入基准，B1/B2保留已有结果作为背景，不自动扩展全部实验组合。

本方案主要目标选择“精度提升”，没有预设允许退化的非劣效界值。若结果持平，只记录为精简候选；不在看完结果后定义“基本等效”。若以后转向非劣效目标，应在新比较前登记界值、依据与分析方法。

## 4. B3-R架构定义

### 4.1 历史容量基线P

从报告注入前的历史隐藏特征构造：

$$
s_i=[H_{T,i},\overline H_i,H_{T,i}-H_{1,i},e_{tod},e_{dow}]\in\mathbb R^{120}.
$$

P为`Linear(120,16) → ReLU → Linear(16,4)`，末层不接sigmoid：

$$
p_i=P(s_i),\qquad c_i^{base}=\epsilon+(1-\epsilon)\sigma(p_i),\qquad\epsilon=0.001.
$$

P仅生成历史条件基线。历史本身可能已包含事故影响，该基线不是无事故反事实容量，4个通道也没有独立的真实物理量定义。

### 4.2 报告条件修正D

$$
v_i=[s_i,E,d_i,\mathrm{age}/5]\in\mathbb R^{156},\qquad
m_i=\mathbf1[\sum_{k=1}^{3}|d_{i,k}|>0].
$$

D为`Linear(156,16) → ReLU → Linear(16,4)`，末层线性，输出delta：

$$
\boxed{c_i=0.001+0.999\sigma(p_i+m_i\delta_i),\qquad\delta_i=D(v_i).}
$$

仅将D末层权重与偏置置零，隐藏层正常初始化。首版不加tanh、幅度系数、单调网络或新正则。允许正负修正；delta为logit变化，不能读作百分比容量损失。

D读取历史是为了根据交通背景使用报告，同时也允许其拟合更多历史模式。因此P/D仍有功能补偿，新结构没有获得唯一可识别的物理分工。

### 4.3 节点容量到边容量

使用明确的新接口接收节点容量c：内部边取`min(c_src,c_dst)`，入口取目的节点容量，出口取源节点容量。外部端点-1显式处理。

旧`state_capacity(a, graph)`先计算`0.001+0.999*(1-a)`；B3-R不能把c直接传入该函数。旧B3行为保持，新接口仅执行容量到边的映射。

### 4.4 交换、边界与主干接入

沿用B3的4维状态、两次子步、eta=0.5、84维提议输入和12→32无偏置读出。容量C既进入提议网络Q，也作为显式边上限：

$$
q_{ij}=Q(\ldots,C_{ij}),\quad b_{ij}=\min(q_{ij},C_{ij}),\quad
x_i'=x_i+0.5(I_i-O_i).
$$

截断后的提议先满足所有出边共享的发送预算，再满足所有入边共享的接收预算。内部边和开放边共同参与相应预算。保留不重新分配受阻余量的现行比例策略，不称为最大通量求解器。

入口/出口提议仍来自报告注入前的历史。容量每次完整前向计算一次；每次局部空间调用重新编码交换状态。五层、每层四次空间调用、每次两子步沿用，共20次调用及40条子步统计。

读出`W[最终状态−初态,平均流入,平均流出]`加入`STLocalizedConv`原图卷积输出。原统计图、时空分支、TIID及预测头继续按原协议训练。隐藏支路有界和收支一致不扩展为主干或最终流量的真实车辆守恒。

## 5. 公共初始化与训练参数契约

从同一个未训练规范B3构造配对初值，逐名称复制保留模块；相同种子不能替代逐参数核对。

1. 复制主干、报告编码器、节点/时间嵌入、LayerNorm、边界头、交换层及相关持久缓冲区。
2. 将A第一层复制到P，A末层权重和偏置取反，得到P=-A；这里A指sigmoid前的logit网络。
3. D隐藏层可复制规范U隐藏层，D末层置零；固定加载顺序，防止后续通用加载覆盖映射。
4. 保存公共参数清单、形状、哈希、映射版本及最终参数量，再构造新优化器。

默认在eval模式、相同输入/设备/精度下核对：新旧历史容量在容差内一致；B3-R自身初始ON/OFF预测一致；B3-R初值与规范B3空间OFF在容差内对应。不要求等于旧B3完整ON或B0。

如果测训练态，应恢复相同随机状态以控制dropout。eval与梯度开关独立：一致性检查可用inference_mode，梯度验收必须启用构图。参见[PyTorch官方说明](https://docs.pytorch.org/docs/2.14/notes/autograd.html#evaluation-mode-nn-module-eval)；此引用不要求改变服务器既有环境。

“源码版本固定”指实现快照固定，**不冻结训练参数**。保留模块按原协议联合训练；共享报告编码器可同时受D与TIID影响，不要求其训练后输出与旧B3相同，也不为此detach。正式从头比较不继承已训练B3权重或优化器。

## 6. 容量作用的证据链与接入验收

容量作用依次核对：有效D修正 → 节点容量变化 → 边容量变化 → 最终交换响应 → 隐藏读出/预测响应 → 任务损失及验证表现。

### 6.1 必须保留的正反例

| 例子 | 条件 | 预期 |
| --- | --- | --- |
| 两端最小值屏蔽 | c_i=0.3，c_j由0.8降至0.6 | C始终0.3；不能将节点变化直接当作边变化。 |
| 发送预算抵消 | 单边q=0.9，源状态0.1，接收空间0.5；C为0.4或0.2 | 两次均触发边上限，最终f均为0.1，局部容量梯度为0。 |
| 接收预算抵消 | 单边q=0.9，源状态0.8，接收空间0.1；C为0.4或0.2 | 最终f均为0.1，局部容量梯度为0。 |
| 非退化容量正例 | q=0.7，C=0.2，源状态0.8，接收空间0.9 | f=C，局部导数为1。 |
| 多出边比例抵消 | 共享发送预算饱和，候选容量共同按比例缩放 | 分配比例及最终交换可能不变，不能预期每条边都响应。 |
| 总作用不保证单调 | q(C)自身可随C下降而上升，且q<C、收发预算宽松 | 满足硬上限仍可能出现容量下降、最终f上升。 |

本轮已用未修改的B3算子完成六组合成核验，见[结果JSON](verification/igstgnn_b3_r_capacity_path_examples_20261012.json)及[复现脚本](verification/verify_b3_r_capacity_path_examples_20261012.py)。最后一例的q为人为构造的`sigmoid(1-2*C)`，不是训练网络实测。上述结果只验证局部算子和解析边界；随后开发已通过完整B3-R主损失受控启动检查，见[工程验收](verification/igstgnn_b3_r_implementation_20261012.json)，不扩展为真实数据收益。

### 6.2 完整主损失的梯度启动检查

构造报告端为明确瓶颈、收发预算有余量、D部分ReLU激活且读出方向对损失有响应的完整模型正例，检查最终预测损失到D的路径。首次反向后记录末层和隐藏层的任务梯度，更新、清梯度并重新前向，再检查后续隐藏层梯度。

零末层初始化时，首次隐藏层任务梯度为零是预期行为。非退化正例应能启动学习，但不要求任意真实批次、所有通道或所有参数在第二步都非零。weight decay造成的参数变化不能算作任务梯度证据。

另保留预算抵消等预期零梯度反例。有限差分选择远离两端相等、q=C、预算刚好饱和和ReLU零点的位置；分支交界处的方向差异不直接判为错误。真实批次持续无响应时按证据链逐段定位。

容量的有界性与硬上限不保证端到端交换单调，更不保证事故一定降容或相关预测一定下降。首轮记录该边界，后续单调结构需单独立题。

## 7. 诊断、统计与开关定义

### 7.1 模型接口与长期日志分离

模型接口清楚提供基线/更新后的节点容量与边容量、原始delta、有效m*delta及必要logit。它们有派生关系，长期日志不重复保存完整张量或计算图。

| 统计 | 累计单位与含义 |
| --- | --- |
| logit、有效修正、节点/边容量差、饱和或sigmoid斜率 | 每个完整前向累计一次；全图和报告关联条件统计分别记录分母。 |
| 报告端瓶颈比例、端点近似相等比例 | 按关联节点—内部边—通道关联计数；开放边另列；数值容差随schema登记。 |
| 最终交换、预算限制、状态范围、收支误差 | 按实际层/调用/子步累计；保持40条覆盖检查。 |
| 实际容量到最终f的局部敏感性 | 在选定受控批次或配对探针计算，不用容量截断率替代。 |
| D任务梯度 | 受控启动验收及固定诊断批次记录；区分None、0与非零。 |

只在日志路径detach，实际进入Q和交换的容量继续保留梯度。完整张量仅对选定批次按需导出。原adoption字段不伪装为新结构中的采用率；所有消费者，包括导出与分析脚本，都需迁移schema。

### 7.2 空间修正OFF

OFF令c=c_base，可以跳过D。此时原始`report_logit_delta`标记未计算，有效修正为零，更新容量等于基线；不把跳过D记为“D学到了零”，也不为补日志而额外执行D。

TIID保持ON，历史交换继续工作。D读取历史，关闭它也减少有效历史条件处理能力，所以该对照只回答整条条件修正路径的价值。

中性报告信息对照后置，需逐项定义E、显式年龄、d与m的处理，并保持可比的历史处理能力。E内含年龄，只清除显式年龄并不充分；只将m置零则相当于关掉路径。保留TIID是否合适取决于研究问题。

对照仍保留目标报告信息属于消融不完整或信息控制问题；截止时刻之后才可得的信息进入输入或训练，才属于相应时间泄漏问题。两项分别审查，不据此擅自关闭原TIID。

### 7.3 同检查点探针

验证选出的同一检查点依次执行ON复现、OFF、ON恢复，固定输入、原评估batch划分、设备、精度及运行模式。初始复现失败则阻止OFF结论，最终恢复失败则不标记探针完成。

检查参数及缓冲区未变、无优化器更新，异常时清理所有干预。按节点容量、边容量、最终f、读出及预测分别记录变化；流量误差差值统一为`MAE_OFF−MAE_ON`。该探针是检查点敏感性，不是报告的因果效果或从头训练收益。

## 8. 训练协议与预先规定的评价

### 8.1 沿用现有训练预算

| 项目 | 设定 |
| --- | --- |
| 首轮种子 | 2025；规范公共初始化显式配对。 |
| batch | 48。 |
| 优化器 | Adam，lr=0.002，weight_decay=1e-5，eps=1e-8。 |
| 梯度裁剪 | norm=5。 |
| 学习率 | milestones=[1,38,46,54,62,70,80]，gamma=0.5，调用顺序沿用现有实现。 |
| 上限与早停 | 最大100轮，patience=20，min_delta=0；继续训练的epochs为累计轮次。 |
| 训练目标 | 既定有效流量MAE；不增加容量伪标签、辅助损失或旧M4残差目标。 |
| 主要选模指标 | 全496站、12时距的既定horizon-macro验证MAE；严格按同一规则保存最佳检查点。 |

旧B3结果只有在数据、预处理、图、公共初始化及训练协议可核对时才能复用；相同seed本身不足以证明可复用。新增比较使用自己的架构身份，不恢复旧优化器。

### 8.2 分阶段运行

1. 工程检查与完整1轮：检查形状、公共初值、梯度启动、预算约束、日志及保存/恢复。此阶段不作精度结论。
2. 累计10轮：观察优化曲线、数值与机制。第10轮MAE没有超过B3，不构成结构无效的充分依据，也不预设零初始化必需固定预热轮数。
3. 共同预算下完成首轮比较：按同一上限、早停和选模规则比较B3/B3-R，曲线在共同轮次对齐；不能用R第10轮对B3第100轮最佳值排名。
4. 完成空间OFF从头训练及同检查点探针；按结果判断路径价值和后续研究问题。
5. 若进入复核，拟登记2025、2026、2027三组配对种子，优先只扩展旧B3与B3-R。若要声称路径收益跨种子稳定，OFF也需相应复核。

明确工程错误、持续非有限值或约束违规应先修复。资源不足可以提前停止，但记录为预算决策及实际完成轮次，不把早期排名写成最终效果结论。

### 8.3 成功标准与统计单位

定义每个配对种子的收益`gain=MAE_B3−MAE_R`及相对收益。首轮gain>0只是候选信号；后续三配对种子的平均收益为正且方向均为正，作为一致性支持。若方向混合，报告异质性，不认定稳定改进。三种子一致仍不自动构成统计显著性或泛化认证。

同时报告收益绝对量、相对量、种子间波动以及实测时间/显存；微小正数不自动等于实际价值。持平或退化不转写为等效，结构更简单本身不能替代主目标。

次要指标预先固定为：原报告直接关联节点、候选结构潜在关联区域、算子覆盖外节点、已有道路分组以及各预测时距。无有效目标的区域标记不可用，不填零；结构潜在范围不命名为实测传播范围。

按可靠事件标识汇总事件差异，随机种子与事件差异分开报告。相邻窗口、站点和时距不作为独立重复。区间估计如实施，按可核查事件/日期相关结构聚类，并处理共享目标造成的相关性；事件身份不可靠时只作相应描述，不虚构独立簇。

## 10. 结果如何反馈模块设计

| 观察 | 优先解释与下一行动 |
| --- | --- |
| D有效修正长期很小 | 先核对任务梯度、掩码与优化，再判断当前输入是否提供增量；不立即认定报告无用。 |
| 节点变、边不变 | 检查瓶颈端屏蔽与位置关联；这是结构选择问题，不自动是代码错误。 |
| 边变、最终f不变 | 检查收发预算及比例抵消；容量截断率不能代替响应证据。 |
| f变、预测不变 | 检查读出方向、主干补偿及数值尺度。 |
| 预测变、总体MAE持平 | 分解正负收益、预定区域及事件差异，不挑选有利子集替代主指标。 |
| R优于B3，但同检查点OFF与ON接近 | 只说明该权重敏感性低；仍需独立重训练OFF判断路径价值，不把结构收益归因于报告。 |
| 独立训练OFF与ON接近 | 当前比较未提供清楚的路径收益证据；结合种子不确定性解释，不能直接证明等效。 |
| R稳定改善且路径有价值 | 再研究同P/D下硬边上限及共享预算的贡献。 |

后续无显式边上限组保持C作为Q输入，保留发送/接收预算与有界更新，只将`min(q,C)`换成q；命名应写明这一变化。若研究整体受限交换优于普通交换，必须另配同P/D的普通交换组，不能直接用旧B2隔离该差异。
