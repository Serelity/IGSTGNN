# M4.0：历史状态估计与原预测头融合

2026-10-10。承接服务器M3.0的47项检查。本轮实现从合法历史到截止时刻潜状态、共享条件容量、开放入口预测、辅助观测头及原IGSTGNN预测头前融合。这里的“接入完成”指代码与工程接口；真实有向图和报告集合资格仍未闭合，六组正式训练尚未开始。

## 已实现的信息路径

`src/models/incident_capacity_fusion.py`提供独立组合模型，不安装forward hooks：

1. 历史编码器读取12步flow/occupancy/speed和数值可用掩码。以冻结的原训练期通道均值作asinh参考尺度；它不是潜容量、密度或跨站守恒流量。显式输入标签起点和区间终点，拒绝偏移历史时钟。由共享GRU、历史摘要及末次有效观测结束到t0的间隔估计t0初态；所有历史缺失时返回0.5先验及不可用标记。
2. 每个节点有八维固定历史摘要：三通道均值、末次有效值、速度趋势和有效比例。每条边的公共输入分别保留上下游隐藏表示及各自八维摘要、端点存在标记、边类型和分配权重，不混淆两端身份。历史条件向量为存在端点摘要的平均值；报告条件也为八维。两次系数推断共用同一个MLP，无报告专属可学习投影。
3. 报告接口接收显式`weights[B,R,E]`、年龄、存在掩码、距离和匹配可信度。每个报告的边权和不超过1，不能铺满走廊。八维摘要为存在、对数计数、最小/加权平均/最大对数年龄、加权对数距离、可信度、合成关联强度；空集合为零。`s=1-prod(1-w)`。负年龄、缺席却有权重、未知字段和入口关联被拒绝。**实体去重与可见版本核验仍由后续数据适配完成；张量接口本身不能认证这两项。**
4. 报告仅经四个Bernstein系数改变容量；关闭条件精确返回历史容量。初态和边界预测完全不读取新增报告。全局潜发送/接收速率固定为1，kappa固定为1，发送权重由静态图提供；本轮不学习逐站自由速率。
5. 共享边界MLP由历史生成四个控制点、每个潜通道一条[0,2]需求轨迹，只写入显式入口。内部边和出口的边界需求精确为零。
6. 从t0递推到+65分钟，按原12个目标窗口聚合状态、入流、出流与变化。辅助头和零初始化残差投影只读取这16维递推结果。残差添加在原TIID之后、原输出MLP之前；原ICSF/TIID保留触发事故输入。

原`IGSTGNN.forward`仅增加可选`forecast_delta`参数，默认路径保持原计算。新增残差的轴、设备、dtype及有限性均检查。完整fixed主干的共同权重无需转换，历史checkpoint仍可直接加载到组合模型的`backbone`。

## 普通参照与梯度

容量受限/普通分支共用全部历史、系数、边界、辅助和融合网络的结构与参数轴。普通递推只额外读取同一容量张量，不另读报告。默认新增分支分别为7229和7473参数，普通多244个实际参与计算的转移参数；相同443645参数主干下，完整模型分别450874和451118，差约0.054%。这是披露差额、略充足普通预算的参照，**不是精确参数匹配**。共享部分可直接复制共同初始化。

容量未成为瓶颈时梯度可以为零。工程检查在显式受容量约束的合成场景中验证：初始零投影复现原预测；辅助损失能进入容量网络；投影更新后，单独主预测损失也能进入容量网络。该场景将系数偏置人工设为0.8，仅用于连接诊断；生产模块默认为0.15，不强迫每个报告产生作用，也不以该人工目标证明真实数据可学习或预测改善。

辅助头只提供张量与梯度路径。本轮没有真实辅助监督、历史前缀外推任务或正式损失调参；从完整历史重建同一历史不能代替外推验证。L1局部动态参照尚未实现。

## 原训练清单适配及资格清单

`OriginalCapacityInputs`复用已验真的v11a `train_history.npy`，保持原3604训练记录、496站与X时钟。原主干的输入仍是标准化flow、time-of-day、weekday；新增历史才是flow/occupancy/speed，不混用这两组三通道。归一化来自原训练清单，候选9943 X和它的p95不进入本适配。

真实检查遍历全部原训练历史，检查截止状态的轴、范围与可用性；随后在两条真实历史上核对完整496站主干的初始输出一致。它不打开原`train_flow.npy`、排除区间、Y、val或test交通，不更新真实数据权重。

输出496站、14方向组和全部482条候选连接资格清单。217条元数据预筛通过仍是候选，不自动作为直接边。当前证据没有认证边界、方向直接连接与报告可见集合，因此用于真实输入检查的新增图为空，所有站保持原预测；这是明确的回退验收，**不能当作核心模块覆盖全网或大部分道路的解决方案**。零“已认证”表示证据待补，不表示道路均不适用。

同一截止点的原触发记录保持原清单身份；重复截止点数量写入资格摘要。新增分支的并发报告重建和唯一截止点加权敏感性尚未冻结；不把不同原事故条件的预测当作同一预测。

## 服务器运行

先在终端独立更新`research/chronological-tiid`分支。两个Bash入口均没有Git。在Slurm登录节点直接提交：

```bash
bash experiments/chronological/submit_incident_capacity_fusion.sh
```

提交入口内置V100分区、1张GPU、3个CPU和15分钟时限，内存由集群按CPU核数自动分配。根据服务器实际拒绝信息，已移除显式内存申请；该集群不允许使用`--mem`参数。默认服务器已有igstgnn Python及cuda:0；自动把现有`M40_*`数据环境变量传给作业。显示`Submitted batch job ...`表示提交成功，日志为仓库根目录`slurm-capacity_m40-作业号.out`。可用`M40_PARTITION`或`M40_PYTHON`覆盖分区和Python。若手动指定原v11a历史目录，将其作为该提交入口的唯一参数。

提交入口显式导出仓库绝对路径`M40_REPO_DIR`，并在提交前检查日志和结果目录的写权限。Slurm会运行提交脚本的临时副本，运行入口不能按该副本的位置重新推算仓库；未显式指定仓库路径的Slurm作业使用`--chdir`设置的工作目录。运行入口先核对仓库标志文件并打印实际路径，再在该仓库下创建结果目录，避免误入系统目录。

已有GPU分配内直接执行验收：

```bash
M40_DEVICE=cuda:0 bash experiments/chronological/run_incident_capacity_fusion.sh
```

脚本复用已有原v11a历史并自动查找；不下载、安装或重新生成验证数据。若找不到，可传入原目录：

```bash
M40_DEVICE=cuda:0 bash experiments/chronological/run_incident_capacity_fusion.sh /实际路径/原v11a历史目录
```

可用环境变量`M40_PYTHON`、`M40_DATA_DIR`、`M40_SENSORS`、`M40_HISTORY_DIR`指定既有资产。默认设备CPU，并在日志开头打印设备。成功时输出`M40_ENGINEERING_CHECK_PASS`与退出码0；`check/summary.json`分别记录合成接入、原训练X检查和未完成资格。
