# 全网共同输入与事故支持联合审查

2026-10-09，M1.0a 完成。依据用户要求：**主架构的必需输入应在现有数据的大部分路段上同时具备，核心新增机制也要能够实际运行。** 少数走廊有丰富资料，可以做增强和机制检查；“其余节点回退主干”或“共享参数可能迁移”不能替代这一设计要求。当前没有冻结最终物理架构。

## 审查结果

审查完整 496 站、14 个道路方向组、3,604 个训练窗口；未应用 40 站选择条件。重叠历史去重为 28,320 个名义时间标签，并检查重复值一致。只使用训练 X、图及身份/道路元数据，没有读取 gap/Y、验证或测试数组，也没有训练模型。

| 需求或证据 | 当前联合覆盖 | 架构含义 |
|---|---|---|
| 三通道历史在同站同时间同时有限且非负 | 496/496 站，14/14 方向组；14,046,720 个站时单元全部通过 | 可以作为共同数值输入；不能据此认证原始观测质量、单位或源插补 |
| 站点道路、方向、坐标、源里程与学习图连接 | 与上述历史交集为 496/496 站 | 支持共享模型输入及匹配审查；学习图不等于物理直接连接 |
| 训练中至少一次非零 `report_location_v1` 直接关联 | 230/496 站（46.37%），6/14 方向组 | 事故正支持范围有限；不是“其余站没有事故”或“无法输出预测” |
| 同向按源里程排列的相邻候选 | 482 对；217 对仅通过元数据预筛，261 对包含已知非主线点 | 不是 217 对已满足 CTM；两项计数不是完备互斥分类 |
| 单位/聚合、真实连接、物理长度、观测映射及边界联合满足具体方程 | 尚未建立覆盖率 | 不能将严格 CTM 或局部物理指导自动确定为合格的全网主架构 |

数值可用规则允许真实零值，但无法识别来源中已有的插补。三通道名称沿用 v11a 的来源推断；流量/占有率/速度的物理量纲、聚合仍未认证。没有把每一项各自存在的比例相加或平均来充当联合覆盖。

## 事故支持为何只覆盖部分道路

读取与冻结 context 清单 SHA-256 一致的事件身份旁表，仅对训练 manifest 指定的 3,604 条记录核对事件 ID、报告时间和路段。用原 `prepare_context.spatial_features` 逐条重算，全部与训练 context 精确一致。

| 事件道路方向 | 训练事件/窗口 | 网络该组站点数 | 至少一次直接关联站点数 |
|---|---:|---:|---:|
| SR4-E | 1,269 | 85 | 85 |
| SR4-W | 1,308 | 86 | 86 |
| SR24-E | 290 | 21 | 21 |
| SR24-W | 309 | 21 | 21 |
| SR242-N | 214 | 9 | 9 |
| SR242-S | 214 | 8 | 8 |
| I80、I680、I580、SR160 两个方向合计 | 0 | 266 | 0 |

这说明限制已经存在于冻结训练事件身份中，不是本次三条开发走廊的过滤造成的，也未发现重建 context 与既定关联公式不一致。此核对没有独立认证原始事件定位公式或最初样本筛选的正确性；尚不能解释作者/上游为何只保留这些事件，更不能推出完整事故源没有其他道路事件。

零关联是合法输入状态，不应人为补成“有事故”；间接跨道路交通影响也不等于这里的直接报告支持。必须区分：全网交通监督、各道路事故正样本覆盖，以及未见道路上的机制迁移。当前全网交通数据可用，不代表已验证多数道路上的事故响应。

## 据此修订架构要求

1. 每个核心模块先列明训练与推理必需输入、单位/含义、缺测处理及对应物理假设；计算它们在同批道路、站点和时间上的交集。报告节点、方向组、候选区间和事件各自分母，不能只看站点总百分比。
2. 主模型优先依赖共同交通历史、原有报告时间/位置接口、既有道路基本属性。历史封道更新、逐匝道流量、精细几何和队列真值暂列增强信息；不能因少数走廊可取得就提升为全网必需输入。
3. 物理结构仍须有可检验的供需、容量或传播含义。单位未知时不能把潜变量命名为真实容量，连接/边界条件不成立时不能靠调低约束权重补救。最终采用何种物理形式，需要在共同输入及必要条件审查后确定。
4. 原 A 直接 CTM 与 B 共享状态加局部物理指导均为候选。B 仅在少数地方接受物理指导，也不自动满足用户的大部分路段要求。需分别说明核心路径能否广泛运行、物理依据在哪里成立、事故训练是否充分。
5. “大部分”尚未给定数值阈值，本次报告实际覆盖，不冒称已达到用户批准的 80% 或 90%。冻结架构前确定数量与道路类型代表性要求；不能在看到收益后改变准入范围。

## 下一小任务 M1.0b

先完成两项有限核对，再选择主架构：追溯冻结事件样本的路段筛选，并盘点已下载事故源中其他道路的训练期可定位记录及对应交通历史是否可取；明确候选物理形式在共同三通道数据上所需的单位/聚合证据。单有事故 CSV 不代表能形成新训练窗口，不改动现有冻结基准来填充缺口。若确需扩展，另建有来源与固定时间划分的数据版本，并保留原协议对照。

之后交付核心输入—联合覆盖—物理假设表及架构选择，决定哪些资料必须补证、哪些模块必须简化、哪些只能保留为局部参照。先解决影响多数道路的共性条件，再继续精细匹配开发走廊。M1.0a 不等于 M1.0 架构验收完成。
